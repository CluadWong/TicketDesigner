### 列宽设置失效 bug（第 39 续）
- 现象（用户）：选中 grid → 列数改 2 → 第1列宽填 30mm → 不生效；点 paper 再点回 grid → 第1列变回 1fr。
- 根因（复现测试坐实，非猜测）：
  1. **主因**：`useSchemaEdits.parseColumnWidth` 不认 `mm` 后缀。标签写"列宽（mm / fr / auto）"，用户照填 `30mm` → `parseColumnWidth("30mm")` 判 `INVALID` → `updateGridColumnWidth` 直接 return 不提交。schema 仍旧，重选时 `node.columns?.[0] ?? cell.width ?? '1fr'` 落到 1fr（"没生效+变回1fr"）。裸 `30` 其实正常。
  2. **潜在 bug**：`resizeGridV2`（`schema-v2-operations.ts`）只重建 `rows`，**不同步 `grid.columns`**。渲染层 `GridSchemaNode.vue` L123-127 优先用 `columns` 作真源。默认 grid `columns` 本为 `undefined`（靠 `deriveGridColumnsV2` 重推才没炸）；但一旦设过宽（`columns` 变真实数组）或样例自带 `columns` 后，再 resize 会使 `columns` 长度错位/缺失 → 后续设列宽渲染不到。
- 修复：
  1. `parseColumnWidth` 增加 `^(\d+(?:\.\d+)?)\s*mm$` 分支，剥离 mm 后按毫米数处理（非法 mm 仍 INVALID）。
  2. `resizeGridV2` 重建行后补 `const columns = (rows[0]?.cells ?? []).map(cell => cell.width ?? "1fr"); return { ...node, rows, columns };`，长度对齐首行格数、保留既有宽、新列默认 1fr。
- 测试：临时复现测试 `repro-colwidth.test.ts` 验证后删除；正式回归加 3 例——`useSchemaEdits.test.ts` 列宽块补 `30mm`/`20 MM`→数字提交 + 改2列后设第2列 `columns[1]===40`；`schema-v2-operations.test.ts` 补 `resizeGridV2` 缩2/扩4列 `columns` 同步。
- 验证：vue-tsc 干净；全量 vitest **274/274（33 文件）**（271→274）。未经 git 提交（按惯例）。
