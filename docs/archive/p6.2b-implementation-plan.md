# P6.2b 实现方案（方向 1：Grid 默认 + cell 仅覆盖 padding/align，cell 禁删）

> 状态：已定方向，待代码恢复后落地。
> 前提：当前工作区源码缺失（仅 `.workbuddy/memory`），本方案为代码恢复后可直接套用的改动清单。

## 1. 目标与边界（关键）

**目标**：支持单元格内边距（padding）与对齐（align）配置；Grid 级设默认，cell 可单独覆盖。

**边界（方向 1 的核心约束）**：
- cell 仅作为「样式可编辑」的选中实体，**不可删除、不可拖拽排序、不进入左侧节点树**。
- 删除保护：选中 cell 时「删除选中节点」按钮禁用（或 no-op + 提示）。
- 节点树跳过 cell；cell 通过画布直接点选（与节点点选共用 `data-node-id` 命中）。
- 对齐/内边距采用 CSS 继承式级联：cell 覆盖 > Grid 默认 > 常量默认。

## 2. 改动清单（按文件）

### 2.1 `src/types/schema-v2.ts`

`Grid` 增加 Grid 级默认：
```ts
interface GridNodeV2 {
  // ...existing
  cellPadding?: string;                       // 如 "2mm" / "4px"，Grid 内所有 cell 的兜底
  cellAlign?: CellAlignV2;                    // Grid 级默认对齐
}

interface CellAlignV2 {
  horizontal?: 'left' | 'center' | 'right';
  vertical?: 'top' | 'middle' | 'bottom';
}

interface GridCell {
  // ...existing（rowSpan/colSpan 等）
  padding?: string;                           // cell 单独覆盖
  align?: CellAlignV2;                        // cell 单独覆盖
}
```
常量（建议放在本文件或 operations 内）：
```ts
export const DEFAULT_CELL_PADDING = '0';      // 与现有渲染一致，避免快照回退
export const DEFAULT_CELL_ALIGN: Required<CellAlignV2> = { horizontal: 'left', vertical: 'top' };
```
向后兼容：旧 schema 的 cell 无 `padding/align` 字段 → 走 Grid 默认 → 走常量默认。

### 2.2 `src/types/schema-v2-operations.ts`

- 新增 `updateCellV2(schema, cellId, patch: Partial<Pick<GridCell,'padding'|'align'>>): SchemaV2`
  - 不可变：深拷贝路径上节点，更新目标 cell；`cellId` 不存在时返回原 schema（或抛错，保持与其它 op 一致）。
  - 复用现有「按 id 定位 GridCell 并替换」的遍历逻辑（参照 `updateSchemaNodeV2` 的 immutable 写法）。
- 新增级联解析（**核心**）：
```ts
export function resolveCellPadding(cell: GridCell, grid: GridNodeV2): string {
  return cell.padding ?? grid.cellPadding ?? DEFAULT_CELL_PADDING;
}
export function resolveCellAlign(cell: GridCell, grid: GridNodeV2): Required<CellAlignV2> {
  return {
    horizontal: cell.align?.horizontal ?? grid.cellAlign?.horizontal ?? DEFAULT_CELL_ALIGN.horizontal,
    vertical:   cell.align?.vertical   ?? grid.cellAlign?.vertical   ?? DEFAULT_CELL_ALIGN.vertical,
  };
}
```
- 确认/扩展 `updateGridV2`（或 `updateSchemaNodeV2` 对 Grid 类型）支持 `cellPadding`/`cellAlign` 的 patch。

### 2.3 选择模型（`buildEditorNodeIndexV2` + `DesignerApp.vue` 的 `selectNode`）

- `buildEditorNodeIndexV2`：**纳入 `GridCell`**，使其可被画布点选。
  - 索引记录含 `{ id, type: 'cell', parentId, path }`；并标记为非可删（类型本身即守卫，无需额外字段）。
  - `selectionPathIds` 深度 +1：`page → grid → row → cell → node`。
- `GridSchemaNode.vue` 渲染 cell 时补充 `:data-node-id="cell.id"`（与现有 `:data-layout-id="cell.id"` 共存）。
- `DesignerApp.selectNode` 的点击命中保持 `event.target.closest('[data-node-id]')`：
  - 因节点元素嵌套在 cell 内，`closest` 自然优先返回最内层 node；无 node 时回退到 cell → 实现「点节点选节点、点 cell 空白选 cell」。

### 2.4 节点树（`NodeTreeItem.vue` / DesignerApp 左侧「结构」面板）

- **保持跳过 cell**：`NodeTreeItem` 仍只渲染 Page/Grid/Text/Field/Table/Image/HTML。
- 理由：cell 不开放删除/拖拽，进树只会增加噪声（N 行×M 列 = N×M 个叶子）。cell 通过画布点选即可。
- 注意：`nodeIndex` 包含 cell（供画布选中/面包屑），但 `NodeTreeItem` 显式 `type !== 'cell'` 过滤，二者不冲突。

### 2.5 Inspector（`DesignerApp.vue` 检查器）

新增两个分支：

**(a) 选中 Grid 时 —— 「单元格默认」段**
- 控件：`cellPadding` 文本输入（如 "2mm"）+ `cellAlign` 水平/垂直分段选择。
- 写入：`updateGridV2(schema, grid.id, { cellPadding })` / `{ cellAlign }`。

**(b) 选中 cell 时 —— `CellInspector` 段**
- `padding` 输入：未覆盖时显示占位/灰字（提示「继承 Grid 默认：X」），填写即覆盖；提供「清除覆盖/恢复默认」按钮（仅覆盖态可见）。
- `align` 分段：水平 left/center/right + 垂直 top/middle/bottom；继承态高亮 Grid 默认值并标注「继承」；可覆盖；可重置。
- 写入：`updateCellV2(schema, cell.id, { padding })` / `{ align }`。
- 当前 effective 值用 `resolveCellPadding/resolveCellAlign` 计算并展示，让用户看到「实际生效值」。

`selectedNode` computed 需能解析 cell（来自含 cell 的 `nodeIndex`）；按 `type === 'cell'` 渲染 (b)，`type === 'grid'` 渲染 (a)。

### 2.6 渲染层（`GridSchemaNode.vue`）

- 每个 `grid-cell` 计算 effective 盒：`const pad = resolveCellPadding(cell, grid); const al = resolveCellAlign(cell, grid);`
- 应用 inline style：
  - `padding: pad`
  - 水平：`justify-content` = `flex-start|center|flex-end`（或 `text-align`，取决于 cell 内部布局；与 `tableCellStyle` 对齐处理保持一致）
  - 垂直：`align-items` = `flex-start|center|flex-end`
- **抽共享工具** `alignToFlex(align: Required<CellAlignV2>)` 放到 `schema-v2-operations.ts` 或 `renderer-v2` 内公共 util，`tableCellStyle` 与 cell 渲染共用，保证语义一致。
- 嵌套 Grid：外层 cell padding 与内层 grid.cellPadding 是**两层独立级联**，各自在其层级解析，无需特殊处理。

### 2.7 拖拽落点（`DesignerApp.vue`）

- `onCanvasDrop` / `onCanvasDragOver` **基本不变**：仍用 `event.target.closest('[data-layout-id]')` 命中目标 cell，再 `appendNodeToCellV2`。
- 仅需确保 cell 同时有 `data-node-id`（见 2.3），与 drop 的 `data-layout-id` 互不干扰。
- 选中 cell（样式编辑态）时丢入模板：仍执行「追加到该 cell」语义，不替换 cell。
- 视觉区分：drop 高亮用 `.v2-drop-target`（已有）；cell 选中高亮复用 node 选中样式 —— 需确认二者不会混淆（建议 cell 选中用更淡的描边，drop 用实色填充）。

### 2.8 删除保护

- 「删除选中节点」handler：若 `selectedNode?.type === 'cell'`，**禁用按钮**（或 no-op + toast「单元格不可单独删除，请删除所在 Grid 或先清空内容」）。
- Grid 删除仍允许（删整棵子树），但建议在 UI 上加一次确认即可（非本方案强制）。

## 3. 级联解析语义（核心）

```
effectivePadding(cell, grid) = cell.padding ?? grid.cellPadding ?? DEFAULT_CELL_PADDING("0")
effectiveAlign(cell, grid)   = {
  horizontal: cell.align?.horizontal ?? grid.cellAlign?.horizontal ?? 'left',
  vertical:   cell.align?.vertical   ?? grid.cellAlign?.vertical   ?? 'top',
}
```

## 4. 风险与注意

1. **三态视觉**：cell 选中高亮 vs drop 高亮 vs node 选中高亮需区分，避免用户混淆「选了 cell 还是 node」。
2. **快照回退**：默认 padding 必须为 `"0"` 才能不触发 `FirstFiveRowsSnapshot` 变更；非零需 re-baseline。
3. **嵌套 Grid**：两层级联独立，渲染各自解析。
4. **删除守卫**：cell 选中时禁用删除是硬约束，避免误删整格内容。

## 5. 落地顺序（建议）

1. schema 类型 + operations（`resolveCellBox`/`updateCellV2`）+ 单测  ← 纯逻辑，风险最低
2. 渲染 effective box + 共享 `alignToFlex` + 渲染单测
3. selection 纳入 cell + `selectNode` 命中 + Inspector（CellInspector / Grid 默认段）
4. 删除保护 + 拖拽 `data-node-id`
5. DesignerApp 集成测试 + 快照复核
6. 更新 `development-plan.md`、补样例（可选）

> 备注：本方案不涉及 `vite build`（按既有约定，非大修改/无新依赖不打包测试）；落地时仅跑 vue-tsc + vitest。
